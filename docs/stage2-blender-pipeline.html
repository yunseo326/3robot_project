2026-08-27 · WSL2 → Windows 이전 이후 첫 세션

배경

3robot_project는 시뮬레이션 전용 소형 이족보행 캐릭터 로봇을 MuJoCo에서 자연스럽게 걷게 만드는 프로젝트다. STAGE 1(순수 RL로 다리 골격 확정)과 STAGE 2(RL 롤아웃을 레퍼런스로 한 모방학습 파이프라인 검증)까지는 이미 통과한 상태였다. 이번 세션의 목표는 사용자가 Blender로 직접 만든 걷기 애니메이션을 STAGE 2 파이프라인이 받아들일 수 있는 레퍼런스(npz)로 변환하는 것이었다 — 즉 RL 롤아웃이 아니라 사람이 손으로 만든 애니메이션을 레퍼런스로 쓸 수 있는지의 첫 실험.

왜 회전값이 아니라 좌표로 역산했는가

자매 프로젝트 2robot_project(사족보행)가 같은 문제를 이미 풀어놓은 게 있어 먼저 그 코드(blender/convert_bvh_to_npz.py)를 확인했다. 예상과 달리 Blender 본의 회전값이 아니라 head/tail 월드 좌표만으로 관절각을 역산하고 있었다. 이유는 명확하다 — Blender 본의 로컬 회전축은 리그마다 제각각인 관례(roll 값)를 따르는데, 이걸 로봇 관절 축과 맞추는 과정에서 생기는 실수는 조용히 틀린 값을 만든다. 반면 "본 끝점이 월드 공간 어디 있는가"는 리그 내부 관례와 무관한, 검증 가능한 사실이다.

다만 2robot의 다리(hip 1축 + ankle 1축)와 달리 3robot의 hip은 yaw·roll·pitch 3축 직렬이라, 허벅지 벡터 하나(자유도 2)만으로는 3자유도를 풀 수 없는 진짜 부정형 문제였다. 해결책: 정강이 벡터까지 함께 써서, 무릎이 굽혀지는 평면의 법선(cross(허벅지방향, 정강이방향))을 hip_pitch 관절의 로컬 Y축으로 직접 대입 — 이러면 회전행렬 두 열이 정해지고 나머지 한 열은 외적으로, 3축은 대수적으로 바로 나온다. 무릎각 자체는 hip 회전과 무관하게 두 벡터 사이 각도로 구해져 항상 안정적이다.

육안 검증 — kinematic replay

사용자가 실제로 만든 걷기 애니메이션(npz_test.csv, 250프레임, 30fps)을 변환한 뒤, 물리 계산 없이 매 프레임 qpos만 그대로 재생(정기구학)해 확인했다.

다리만 — Blender 애니메이션과 비교해 "블렌더랑 똑같다"고 확인됨.

팔은 character.xml에 관절이 없어(STAGE1 규칙: 팔은 질량만 있는 고정 링크) 이번 확인용으로만 임시 아마추어(models/_viz_arms_temp.xml, RL 파이프라인엔 미반영)를 만들어 다리와 같은 방식으로 팔 각도도 역산해봤다.

다리 + 임시 팔 — 팔꿈치가 자주 거의 펴져 있어 어깨 yaw 추출이 다리보다 불안정함(참고용).

STAGE2 스모크 학습

자기충돌을 무시한 채(위 이유로 코드 수정 없이 이미 그 상태) 이 레퍼런스로 50만 스텝 스모크 학습을 돌려, 동작 자체가 학습 가능한지 확인했다. 6코어 사용(8코어 중 2코어는 발열 여유로 비워둠), 20분 작업/7분 휴식 페이싱.
